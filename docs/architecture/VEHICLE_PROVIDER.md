# Vehicle Provider

`VehicleProvider` provides `connect`, `reconnect`, `disconnect`, `getSnapshot`, `subscribe`, `sendCommand`, mission transfer methods, mission validation, and `dispose`. It emits a product-facing `GroundStationSnapshot`, not protocol packets. `sendCommand` accepts only a `VehicleAction` and returns a domain `VehicleCommand`; mission transfers return immediate domain `MissionOperationReceipt` values. Neither exposes protocol fields. `MockVehicleProvider` models bounded values and owns its interval, which `disconnect` and `dispose` clear.

Providers must produce a terminal command outcome (`accepted`, `rejected`, or `timed_out`), prevent a duplicate pending command, and never retry a command silently. Mission transfer lifecycle belongs in `MissionSnapshot`, with one active transfer per vehicle and no silent retries. Adapters must normalize their source at this boundary and must not be imported by dashboard components or Zustand stores.

Connection Settings are validated in `domain/connectionSettings.ts`, persisted under a versioned local-storage key, and applied by `VehicleService.replaceProvider`. The service disconnects and disposes the old provider before subscribing to and connecting the replacement, preventing two active MAVLink listeners. Saving only persists validated values; Cancel restores the last saved values, Restore Defaults changes the editable values, and Apply explicitly persists and reconnects the selected provider.

`ConnectionDiagnostics` in the snapshot is the product-facing status model for the Diagnostics screen. MAVLink counters and timestamps are updated only as accepted MAVLink messages reach `MavlinkVehicleProvider`; transport errors are counted when the transport reports or fails a connection error. Listener liveness comes from the connection lifecycle, and freshness is calculated from the last received message. Copy Diagnostics exports these product-facing fields only, never MAVLink frames or payloads.
