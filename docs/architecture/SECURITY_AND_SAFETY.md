# Security And Safety

The application exposes a deliberately constrained vehicle-action surface: arm, disarm, takeoff, land, and return to launch. Every action requires explicit confirmation, is sent once, and receives an observable accepted, rejected, or timed-out outcome. The UI cannot construct MAVLink frames, mission upload and parameter writes are excluded, and commands cannot be triggered by scripts or AI output. The native boundary only owns UDP receive and send; it has no filesystem, shell, process, serial, USB, or firmware authority. The Tauri capability surface relies on the default minimal core permission set; new permissions require explicit review and documentation.
